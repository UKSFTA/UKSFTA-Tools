# UKSFTA-Tools

Shared tooling for the UKSF Task Force Alpha Arma 3 workspace, written in Rust.

## Usage

Run from a mod repository root (a directory containing `mod_sources.txt` and `addons/`).

```bash
# Preview what a sync would change
uksfta sync --dry-run

# Copy PBOs from the local Steam Workshop cache into addons/, write mods.lock
uksfta sync

# Generate an Arma 3 launcher modlist for missing mods
uksfta sync --modlist

# Custom output path for the modlist
uksfta sync --modlist --modlist-path ./my-modlist.html

# Also resolve dependencies from Steam Workshop pages
uksfta sync --modlist --resolve-deps

# Skip dependency resolution and stay offline
uksfta sync --offline

# Show which PBOs came from which Workshop mod
uksfta identify

# Confirm all locked PBOs are present
uksfta verify

# Audit each mod's PBOs against addons/ (present/missing per PBO)
uksfta audit

# Show only missing PBOs and per-mod counts
uksfta audit --missing-only

# Compare mods.lock timestamps against the Workshop cache
uksfta updates

# Trace untracked PBOs in addons/ back to their Workshop origin
uksfta investigate

# Resolve each PBO's identity online; a title prints only when confirmed
uksfta investigate --online

# Investigate all PBOs, including tracked ones
uksfta investigate --all

# Refresh the online resolution, then print the status lines
uksfta investigate --report --online

# Print the stored resolution lines with no network
uksfta investigate --report

# Verify the game server's workshop tree over SFTP
uksfta server

# Upload missing PBOs and signatures, then remove extra PBOs
uksfta server --upload --prune

# Check every required addon is provided by the pack or the external list
uksfta deps

# Include a mission's addons[] list, and fail on an unaccounted addon
uksfta deps --mission mission.pbo --strict

# Show the installed version and force a fresh update check
uksfta version

# Update the HEMTT publish description and changelog
uksfta docs

# Preview the generated text without changing files
uksfta docs --dry-run

# Update every HEMTT project below a directory
uksfta docs --root ../

# Fail when a configured publish file is missing or stale
uksfta docs --check

# Look up missing mod names from the Steam Workshop
uksfta docs --online

# Refetch cached names after a Workshop rename
uksfta docs --online --refresh-names

# Replace a hand-written description or changelog section
uksfta docs --force

# Import mods from an Arma 3 launcher modlist HTML file
uksfta import ./my-modlist.html

# Preview what would be imported without changing mod_sources.txt
uksfta import ./my-modlist.html --dry-run

# Export mod_sources.txt as an Arma 3 launcher modlist
uksfta export

# Export to a chosen path with a chosen preset name
uksfta export ./modlist.html --preset-name "UKSFTA Modpack"

# Print the entries without writing a file
uksfta export --dry-run

# Show each mod's size from a launcher modlist HTML, and the total
uksfta size ./my-modlist.html

# Also fetch sizes for mods not installed locally (Workshop API)
uksfta size ./my-modlist.html --online

# Show the installed pack size per mod from mods.lock and addons/
uksfta size

# Print one line per PBO, and sort the report by name
uksfta size --pbo --sort name
```

## Publish Files

`uksfta docs` reads `.hemtt/project.toml` and acts only when the project
sets a publish path:

```toml
[hemtt.publish]
description = "workshop_description.md"
changelog = "CHANGELOG.md"
```

The command writes the description from the project name, the version
file, and `mods.lock`. It lists the installed mods, then the dependencies
that the content does not already include. HEMTT converts the Markdown to
Steam Workshop format at publish time.

The two paths are used exactly as written. They may have any name or
subdirectory. For example, AEE sets `description = ".hemtt/workshop.md"`
and A3 Accessibility sets `description = "README.md"`.

With `--online`, the command asks the Steam Workshop API for the title of
every entry whose name is empty or the `Mod <id>` placeholder. It leaves
real names alone and makes one request for all missing ids. Resolved
titles are stored in `.uksfta/workshop-names.json`, so later offline runs
keep them. Add `--refresh-names` with `--online` to refetch cached titles
after a Workshop rename.

The changelog follows Keep a Changelog 1.0.0. It records the mods added,
updated, and removed since the previous version, using `mods.lock` as the
source. Only the previous composition is cached, in
`.uksfta/publish-state.json`. Commit that file so a fresh clone and CI see
the same baseline. Every run rebuilds the section for the current version,
so a repeated run produces the same text. A version change starts a new
section. Older sections remain in the file, and the published change notes
remain on Steam.

Generated descriptions end with `[//]: # (generated by UKSFTA-Tools)`, and
every generated changelog section contains the marker. It is a Markdown
link-reference definition, which HEMTT's converter drops, so it never
reaches Steam. A file or section without the marker is treated as
hand-written: the command leaves it alone, and `--check` reports it. Use
`--force` to replace it.

HEMTT 1.22 looks up the changelog with the full version string, but its
parser accepts only `major.minor.patch`. The changelog therefore uses the
three-part form. To let `hemtt publish` find the entry, set
`[version] git_hash = 0` and remove `BUILD` from `script_version.hpp`. The
command warns when the project does not meet this.

Run `docs` in a project root. Use `--root <PATH>` to search a directory
tree for `.hemtt/project.toml` files. `--dry-run` prints each target and
the generated text without writing files. `--check` writes nothing and
exits 1 when a target is missing or stale, so it can gate a build.

The command is offline unless `--online` is given. A project without
`[hemtt.publish]`, with no readable version, or with no `mods.lock` is
reported and skipped. The previous file is kept as `.bak`.

### CI

Run this step before `hemtt publish`:

```yaml
- run: uksfta docs --online --check
```

The step fails when a publish file is stale, so the release stops before
it uploads old text. To upload regenerated text, run `uksfta docs
--online` earlier in the job and commit the result, or run it in the
release job before `hemtt publish`.

## Input Format

`mod_sources.txt` supports two formats. The TOML format (v2) adds metadata
per mod and is written automatically when a legacy file is first read (a
`.bak` backup is kept):

```toml
version = 2

[[mods]]
id = "https://steamcommunity.com/sharedfiles/filedetails/?id=887302721"
name = "Boat Mod"
tags = ["vehicles"]

[[mods]]
id = "450814997"
name = "CBA_A3"

[[mods]]
id = "https://steamcommunity.com/sharedfiles/filedetails/?id=463939057"
role = "ignore"
enabled = false
```

Fields per mod:

- `id` — Steam Workshop item ID, or the full Workshop page URL. URLs are
  easier to verify at a glance; both forms are accepted. When a legacy
  file is migrated, ids are written as URLs so entries stay clickable.
- `name` — display name, shown in sync output
- `tags` — optional array of tags
- `role` — `mod` (default) or `ignore`
- `enabled` — set `false` to exclude without deleting the entry
- `dependencies` — array of required Workshop IDs. `sync --resolve-deps`
  writes discovered ids here automatically, sorted and de-duplicated.

The legacy format (v1) is still accepted: one Workshop mod per line (URL
or bare ID), with an optional tag after `#`. Mods under `[ignore]` are
excluded (for example the base dependency set that is not repacked).

```text
https://steamcommunity.com/sharedfiles/filedetails/?id=887302721 # Boat Mod
450814997 # CBA_A3

[ignore]
463939057 # ACE
```

## Output

- `addons/` — PBOs copied from the Workshop cache
- `mods.lock` — JSON manifest of synced mods (files, name, tags, dependencies, last-updated timestamp)

The tool reads the Workshop cache and its `appworkshop_107410.acf` metadata
directly from your Steam libraries. It is offline by default. `investigate
--online`, `size --online`, and `sync --resolve-deps` use the network, as
does the automatic update check, which calls the GitHub API.

The `audit` command also flags orphan PBOs: files in `addons/` that belong
to no mod listed in `mod_sources.txt`. These are leftovers from removed
mods and can be cleaned up. It exits with a non-zero status when any
expected PBO is missing, so it can gate a build in CI.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Success, including "nothing to do". |
| 1 | A check failed. `verify` or `audit` found a missing PBO, `sync` found a required dependency absent from the cache, or `docs --check` found a missing or stale publish file. |
| 2 | Input or environment failure. A required file is missing or unreadable, or `mod_sources.txt` or `mods.lock` is unparseable. |

Network failures during `--online` commands are warnings and exit 0. Those
commands are best-effort. The one exception is `docs --online --check`: a
failed Workshop name lookup leaves the description stale, so `--check`
exits 1.

## Missing mods

When a mod in `mod_sources.txt` is not present in any local Workshop
cache, `sync` reports it with its name and a direct link to the Steam
Workshop page, then lists a set of `steam://url/CommunityFilePage/...`
deep links so each mod can be subscribed to in Steam. Once subscribed
and downloaded, re-run `uksfta sync` to pull the PBOs into `addons/`.

Use `--modlist` to generate an Arma 3 launcher preset file (HTML) that
lists all missing mods. Open the file in the launcher to batch-subscribe
to every missing mod at once. The output defaults to `missing-mods.html`;
override with `--modlist-path`.

Add `--resolve-deps` to fetch the Workshop page of every enabled mod. It
discovers dependencies not listed in `mod_sources.txt`. Resolution covers
every enabled mod, not only the missing ones.

A discovered dependency that is already in the Workshop cache is repacked
into `addons/` and recorded in `mods.lock`. A later plain `sync` keeps it.
A discovered dependency that is absent from the cache is reported missing
and added to the modlist.

If a required dependency is absent from the cache, `sync` fails with exit
code 1. It fails before it copies any PBO, so a broken mod is never
published. The non-mod Steam app ids `107410` and `228800` are ignored.
This requires a network connection and adds a one-second delay per mod for
rate limiting. A page that does not load is a warning for that mod, and
the run continues. When no Workshop page loads at all, `sync --resolve-deps`
exits 2 and resolves no dependencies.

## Importing a modlist

Use `import` to add mods from an Arma 3 launcher preset file (HTML) to
`mod_sources.txt`:

```bash
# Add all Steam mods from a shared modlist
uksfta import ./my-modlist.html

# Preview first — prints what would be added, changes nothing
uksfta import ./my-modlist.html --dry-run
```

Each Steam mod is appended as `{id} # {name}`. Mods already present in
`mod_sources.txt` (including the `[ignore]` section) are skipped. Local
mods without a Workshop ID are skipped with a warning. New entries are
inserted before the `[ignore]` section if one exists.

## Exporting a modlist

Use `export` to write every enabled mod in `mod_sources.txt` as an Arma 3
launcher preset file (HTML):

```bash
# Write modlist.html in the current directory
uksfta export

# Write to a chosen path
uksfta export ./out/modlist.html

# Set the preset name shown in the launcher
uksfta export --preset-name "UKSFTA Modpack"

# Print the entries and write no file
uksfta export --dry-run
```

The output path defaults to `modlist.html` in the current directory. The
preset name defaults to the name of the current directory, and falls back
to `UKSFTA Modpack` when that name is not usable. `--preset-name` sets the
name in the `arma:PresetName` meta tag and the page heading.

Entries with `role = "ignore"` or `enabled = false` are left out. The mod
order follows `mod_sources.txt`. A source name of `Mod <id>` is replaced
by the name in `mods.lock` when the lock holds one.

`--dry-run` prints the entries that would be written and writes no file.

The output is a normal launcher preset, so `uksfta import` reads it back.

Local mods cannot be exported. `mod_sources.txt` holds Workshop ids only,
and a local mod has no Workshop id.

## Modlist size

Use `size` to list the download size of every mod in an Arma 3 launcher
preset file (HTML) and the total:

```bash
uksfta size ./my-modlist.html
```

Sizes come from the local Workshop cache (`appworkshop_107410.acf`), so
no network access is needed. A mod that is not installed locally is listed
as `unknown` and is left out of the total. Local mods without a Workshop
ID have no size and are reported separately.

Add `--online` to fetch sizes for mods not installed locally from the
keyless Steam Workshop API (`GetPublishedFileDetails`). One request covers
the whole list, up to 100 ids per call. Without the flag the command stays
offline.

When the output is a terminal, each size is coloured by its share of the
total: green under 5%, yellow under 20%, red at or above 20%. Mods with no
known size are shown in grey.

### Installed pack size

Run `size` with no file to report the installed size of each mod in
`mods.lock`. The command reads every PBO path in the lock and measures
the file in `addons/`:

```bash
uksfta size
```

The report is sorted by size, largest first. Each line shows the size,
the share of the tracked total, the mod name, the Workshop ID, and the
PBO count. The command also reports PBOs that no lock entry tracks and
locked PBOs that are absent from `addons/`. A missing PBO adds no bytes
to the total.

Add `--pbo` to print each PBO and its size under its mod. Add `--sort name`
to sort the report by mod name in case-insensitive order. The default order
is by size:

```bash
uksfta size --pbo
uksfta size --sort name
```

With `--pbo`, the command also lists each untracked PBO with its size and
the name of each locked PBO that is absent from `addons/`. Enabled mods in
`mod_sources.txt` that are not in `mods.lock` appear under `Not installed`,
with the name and the Workshop ID. The command stays silent when there is
no `mod_sources.txt`. It prints a warning to stderr when the file exists
but cannot be parsed.

## Investigating PBO origins

Use `investigate` to trace PBOs in `addons/` back to their Workshop
origin. By default it examines PBOs not tracked in `mods.lock` — leftovers
from removed mods, merged packs, or manual copies:

```bash
# Trace untracked PBOs to their source Workshop mod
uksfta investigate

# Resolve each PBO's identity online and confirm the name
uksfta investigate --online

# Investigate every PBO, including tracked ones
uksfta investigate --all

# Refresh the online resolution, then print the status lines
uksfta investigate --report --online
```

Each PBO is matched by its **header prefix** (the addon's canonical path,
e.g. `z\ace\addons\grenades`) against the local Workshop cache, then the
winning mod's `meta.cpp` gives its Workshop ID and name. The prefix
survives re-packing, so a repacked copy still resolves to its original
mod. When a PBO exists in multiple cache folders, the standalone mod is
preferred over aggregate packs (identified by spanning many distinct
prefix roots). PBOs with no matching copy are reported as unknown — they
may come from a deleted or private mod, or be manually placed. A result
whose best match is itself a pack is flagged `[pack: verify source]`.

With `--online`, the tool also calls Steam's `GetPublishedFileDetails` API
(no key required) to report whether each origin still exists and is
publicly visible. An item that is not publicly visible is either removed
or set private — the API cannot tell the two apart without the owner
authenticating.

The same run then resolves the identity of every examined PBO from its own
content. It reads the `CfgMods` name, a bracketed author tag, the
`CfgPatches` class and URL, the display names, and other title-shaped
strings that are rare in the pack. It plans at most three Workshop text
searches per PBO, most specific first, and stops at the first confirmed
match.

A search result confirms only when the title covers the query phrase, the
head noun agrees, the result set is narrow, and the best candidate leads
the next one by a wide margin. Content corroboration may rescue a missing
head noun or a thin margin, but never a title that matches the query
weakly. A PBO whose config carries its own Workshop URL confirms on that id
alone.

Evidence comes from every authored-text entry, not only the config. Strings
that are rare in the local pack, stringtable values reached through
`$STR_*` references, and facts recovered from a binarised `\0raP` config
all feed the same gates. A query token of three to six letters may match a
contiguous run of title initials, so `ADE` can match `Advanced Diving
Environment`. The category of a `CBA_fnc_addKeybind` registration is read
as a mod-name source of its own, because modders usually put the title or
the Workshop name there. Two distinct queries that agree on the same item
confirm it even when the per-query margin is a tie, but only when a link
ties that item to this file: a Workshop URL in its config, a dependency
root, the uploader name, or the item page itself. The agreed item must also
lead every rival in the result pool by the same margin a single query would
need, so a family of six identically titled variants stays ambiguous.
Agreement on a generic title never confirms, and a shared word such as
`markers` or `backpacks` is not a link. Popularity never orders or confirms
a candidate.


A tie is resolved by content where possible: the tied candidates' item
pages are checked for the PBO's stem, prefix or `CfgPatches` class, then
for the uploader name. Exactly one match confirms the id. Otherwise the
line keeps the shared title. Unconfirmed clusters with a specific query may
fetch page 2 of the Workshop search, and rarity is learned from every
installed Workshop PBO rather than the pack alone.

When several candidates tie on the same exact title, the line reports the
words they share as a shared title and prints no id, so a family name is
never turned into a guessed Workshop id.

The item page supplies the uploader's name. It is used only as
corroboration, and only when every title gate already passes, because the
uploader is often a repacker rather than the original author. Each item
costs one read however many PBOs point at it.

The store also records the top ten candidates for each PBO. After a run,
`tools/calibrate.py` compares those against `.uksfta/labels.json` and
prints precision at rank 1, 3 and 10 by status. A run reuses a fresh
record while the PBO fingerprint matches, and orders the rest by oldest
attempt. A scan has no request ceiling: it paces every query, waits out a
rate limit with an exponential backoff, and continues until the pack is
done. One line is rewritten in place while it runs, with the completed
queries, the percentage, the elapsed time, the estimated time remaining and
the PBO in hand:

```text
  [ 41/163  25%] 03:12 elapsed  ETA 09:31  esp_objects
```

The output is one line per PBO. A confirmed match prints the title and the
Workshop id:

```text
[confirmed] ade_core.pbo -> "ADE - Advanced Diving Environment" (1891978580) [query "Diving Mask", M=1.00 Q=0.83 margin=1.00]
```

Every other PBO prints a status, a score, and no name. The status is one of
`[ambiguous]`, `[no-query]`, `[no-result]`, `[rate-limited]`, or
`[unresolved]`. A name appears only when it is confirmed, so a doubtful
candidate never prints as a mod title. The summary counts each status.

The browse endpoint is paced at one request every four seconds, so a large
pack with many unseen PBOs takes minutes per run. A rate limit waits and
retries with a growing delay, up to five times, and only then records that
PBO as rate limited. The rest of the scan continues.

Every resolution is written to `.uksfta/identities.json`, so a later run
prints the same lines with no network. The file is keyed by PBO file name
and guarded by the PBO fingerprint, and it is gitignored. A record carries
a title only when the match was confirmed.

```bash
# Print the stored resolution lines, offline
uksfta investigate --report

# Resolve first, then print (refreshes what the run reached)
uksfta investigate --report --online
```

`--report` reads `.uksfta/identities.json` and fingerprints every PBO in
`addons/`, so it reads the PBO file contents as well. A PBO that the file
does not describe, or describes under a different fingerprint because the
file changed, prints `[unresolved]` with no query. A missing file prints

```text
No cached resolutions. Run 'uksfta investigate --online' first.
```

and exits 0. The store records which ranking produced each decision. A
schema or score-version bump therefore discards the whole file instead of
converting it, and the next `--online` run rebuilds it from scratch. A
`[rate-limited]` or `[no-result]` record retries on the next online run.

The store also records the top ten candidates each PBO ranked, so a
mismatch can be examined after the run. `tools/calibrate.py` scores the
store against `.uksfta/labels.json`, which lists the Workshop id a person
has verified for a PBO. It reports precision at rank 1, 3 and 10 for each
stored status, and exits 1 only when a confirmed row names the wrong id.

The `identify` command uses the same byte-hash matching, so its origin
reports are now deterministic too.

## Server verification over SFTP

`uksfta server` compares the private modpack in the local build output with
the pack folder on a game server. The pack id comes from `meta.cpp`. The
command reads and writes only `<root>/@<publishedid>/`. It does not read
`mod_sources.txt`, `mods.lock` or the Workshop cache.

Put the connection settings in `.uksfta/server.toml`. The directory is
gitignored, so the file stays local:

```toml
destination = "user@host"
port = 2022
root = "/"
identity = "/home/user/.ssh/id_ed25519"
host_key_policy = "yes"
known_hosts = "~/.ssh/known_hosts"
```

`destination` and `root` are required. The port defaults to 22. A flag
overrides the file.

### Host key checks

The command checks the server host key on every `sftp` run. It passes
`StrictHostKeyChecking=yes` by default, so an unknown or changed key
stops the run. The key file is `~/.ssh/known_hosts`, unless
`known_hosts` or `--known-hosts PATH` names another file. A leading `~/`
is expanded. A relative path is refused.

`--host-key-policy accept-new` accepts an unknown key once and keeps the
entry. The command prints its own notice when a key is added, because the
client's notice is not shown at `LogLevel=ERROR`. The command never
writes the key file itself. Under the default `yes` policy, a missing or
unreadable key file stops the run before the first connection.

The command also passes `UpdateHostKeys=no`, so a known key is not
replaced without a decision. A host key failure names the destination,
the key file and the remedy.

Run the command from the pack repo root. It reads `meta.cpp` for the pack
id and name, and compares `.hemttout/release` with the server. Use
`--meta PATH` and `--local PATH` to change either. When
`.hemttout/release` is absent, the command uses `.hemttout/build`.

```bash
# Verify the pack against the server
uksfta server

# Compare SHA-256 as well as size
uksfta server --deep

# Print the plan and change nothing
uksfta server --upload --prune --dry-run

# Retry a failed upload up to three times
uksfta server --upload --retries 3

# Upload two files at a time
uksfta server --upload --jobs 2

# Raise the transfer window for a fast link
uksfta server --upload --buffer 261120 --requests 128

# Use the meter path with redirected output
uksfta server --upload --progress

# Prune an extra PBO that mods.lock lists
uksfta server --prune --force-prune
```

The build output must contain `addons/*.pbo`. The command reads every
file under the release root, at any depth. This layout is the usual one:

```text
<root>/@<publishedid>/addons/*.pbo
<root>/@<publishedid>/addons/*.bisign
<root>/@<publishedid>/keys/*.bikey
<root>/@<publishedid>/meta.cpp
<root>/@<publishedid>/mod.cpp
```

The command checks:

1. The remote `meta.cpp` `publishedid` equals the local id.
2. Every local PBO has a case-insensitive match in `addons/`, with the
   same size.
3. Every local `.bisign` pairs with its PBO. Unsigned PBOs are counted,
   not listed.
4. Every local `keys/*.bikey` exists with the same size.
5. `mod.cpp` exists with the same size.
6. Every local `.bisign` names an authority that a local `keys/*.bikey`
   carries, and, when the remote keys are readable, that the remote
   `keys/` carries too.
7. Every other file at any depth is compared by relative path, with the
   same size.

The walk skips four kinds of entry: any name that starts with `.`,
`*.biprivatekey`, `*.tmp` and `*.bak`, and symbolic links. It never
follows a link and never reads file contents. One warning gives the
count of skipped entries.

A remote-only file outside `addons/*.pbo` is `extra` and advisory. Prune
stays inside `addons/` and removes `.pbo` files only, so an included
file, a key, a signature, `meta.cpp` and `mod.cpp` are never removed.
`meta.cpp` and `mod.cpp` keep their own id and size checks.

The default comparison is size only. `--deep` downloads and hashes
`addons/*.pbo` only.

A name that differs only by case is the same file. One warning gives the
number of such names, and uploads reuse the server name, so no case
duplicate is created. A local PBO with no remote match is `missing`. A
remote PBO with no local match is `extra`.

Key matching uses the authority name inside the key file, not the file
name. A renamed `keys/*.bikey` still matches its signatures. A file name
that differs from the embedded authority gives a warning only. The
command reads the authority from the first 4096 bytes of a key. It does
not verify a signature, a hash or a PBO. A key that does not parse is a
warning, and its authority is unknown.

`--deep` downloads each remote PBO into a temporary directory and compares
its SHA-256 with the local file. It is slow, because it transfers every PBO
in the pack. Use it when a size match is not enough.

`--upload` puts every missing or stale file into the pack folder at its
relative path, including files outside `addons/` and `keys/`. It creates
each directory the uploads need, starting with the pack folder, before it
sends the file. After the upload the command lists the server again and
re-runs the check.

### Upload performance

An upload sends the smallest file first. A failure in the middle of a
batch therefore leaves the large files for the next attempt. Each file
uses `put -p`, so the server keeps the local modification time.

The transfer has two settings, and both pass to every `sftp` run,
including the verify phases and each parallel worker.

| Flag | Range | Default | Effect |
| --- | --- | --- | --- |
| `--buffer BYTES` | 4096 to 261120 | 32768 | The size of one write. |
| `--requests N` | 1 to 256 | 64 | The requests in flight. |

The in-flight data for one connection is about the buffer size times the
request count. Both values use memory at each end, so raise them only
when the local link is faster than the transfer. The server accepts at
most 261120 bytes in one write, which is 256 KiB minus 1024 bytes. A
262144-byte buffer fails at once on the local client with `Outbound
message too long`. Throughput is flat from 32 KB to 261 KB on the
current line, about 1.7 to 1.8 MB/s, because the link is saturated. A
larger buffer and more requests help a fast or high-latency link by
reducing round-trip stalls.

An upload attempt re-verifies the pack and retries only the files that
are still missing or stale. The default is 2 retries, which makes three
attempts. Use `--retries N` to change the count. A value of 0 makes one
attempt. The wait is 2 seconds after the first attempt, then 4 seconds.
Each attempt prints the attempt number, the file count, the attempted
bytes, the elapsed time and the rate in MB/s.

`--jobs N` uploads N files at the same time. The default is 1, which is
a single batch, and the maximum is 8. Each job runs in its own `sftp`
process, so parallel uploads need non-interactive authentication. Use an
agent or an identity file. A password prompt cannot serve several
workers.

The gain on the current line is small. Two streams gave 1.80 MB/s. One
stream gave 1.70 to 1.81 MB/s. Use more jobs only on a link with a high
latency. Each attempt puts the files that are still missing or stale
again, and the files are balanced across the workers by size.

An interactive upload shows the client's own meter for each file, with
the percentage, the bytes, the rate and the time left. The meter is on
by default when the output is a terminal and `--jobs` is 1. Use
`--no-progress` to hide it. Use `--progress` to choose the meter path
when the output is redirected. A parallel upload runs without the meter,
because concurrent meters overwrite each other. The verify phases use
`LogLevel=ERROR`, so their output stays parseable.

An interrupted upload restarts the file from byte zero. The command does
not resume part of a file. In testing, `reput` trusted the remote size
and produced a corrupt file of the correct length. Only a complete `put`
gives a file that matches the local copy.

The client also sends `ServerAliveInterval=15`, `ServerAliveCountMax=3`
and `ConnectTimeout=15`, so a dead link fails in seconds.

`--prune` removes remote PBOs that have no local match. It acts inside
`addons/` only, removes `.pbo` files only, and never removes `meta.cpp`,
`mod.cpp`, a key, a signature or a directory. A remote-only PBO that
`mods.lock` lists is kept, because the lock says the pack should contain
it. The command warns about it instead. Add `--force-prune` to remove it
anyway. Without `--prune` the command reports extras and changes nothing.

The command also reads `mods.lock` and `mod_sources.txt` from the repo root
when they exist. It uses them only for warnings:

- a PBO in `mods.lock` that is not in the local release warns
- an enabled mod in `mod_sources.txt` with no `mods.lock` entry warns

A missing file skips its check. Neither warning changes the exit code, and
neither file decides which server folder is checked.

One line reports unsigned PBOs, for example `unsigned: 3 of 114 PBO(s)
have no signature (advisory)`. The line is advisory by default.
`--require-signatures` fails the command when the count is above zero, and
the error names the count.

`--dry-run` prints the plan and stops before any upload or removal. Each
plan line is the command that would run:

```text
plan: put /@3662499431/addons/brf_sumava.pbo from .hemttout/release/addons/brf_sumava.pbo
plan: rm /@3662499431/addons/projeta3019.pbo
```

The command stores no credential and prints none. Authentication is
whatever `sftp` supports: a key, an agent, or a prompt in the terminal. Use
`identity` or `--identity` to select a key. The commands travel on standard
input, so the prompt path stays available. The `-b` batch-file mode is not
used, because it suppresses the prompt. No password is read or stored.

One `sftp` process runs per phase. The phases are the listing, the
`meta.cpp` and `mod.cpp` fetch, the deep download, the upload and the
prune. A password prompt therefore appears at most once per phase. Each run
uses `-R 64` and a 32 KB buffer. See Upload performance for the reasons
and the retry behaviour.

The output starts with the pack id and name, then the local and remote
counts, the status and one line per stale, missing or extra PBO. A single
line gives the unsigned count, and a single warning gives the count of
case-only name differences. The summary counts local PBOs, local-only PBOs
and remote-only PBOs.

The exit code is 0 when the pack matches or only warnings were found. It is
1 for a missing or stale PBO, a key or `mod.cpp` problem, a `meta.cpp` id
mismatch, a missing pack folder, or any unsigned PBO under
`--require-signatures`. It is 2 for a connection, usage or parse failure.

The command never uploads a file outside `<root>/@<publishedid>/`. It never
follows a symlink on the server, and it never recurses below `addons/` or
`keys/`.

## Dependencies

`uksfta deps` checks the addon closure of a built pack. It reads every
`CfgPatches` class that each PBO in `addons/` provides, and every
`requiredAddons[]` entry that each PBO declares. The command is local and
offline. It does not read the Workshop cache, `mods.lock` or the network.

The command reads `.hemttout/release` when that directory exists, else
`.hemttout/build`. Use `--local PATH` to choose another directory. A
missing directory is an input error and names the path.

Each requirement has one of three states:

- `provided`: a PBO in the pack provides the class.
- `external`: the external list names the class.
- `unaccounted`: nothing accounts for the class.

The external list holds the addon classes that the pack needs but does not
provide. These are base-game and DLC addons, and mods that the server or
the launcher supplies. Write one class on a line. A line that starts with
`#` is a comment. The default path is `.uksfta/external-addons.txt`. Use
`--external PATH` to choose another file.

```
# Arma 3 base game
A3_Data_F
A3_Data_F_Loadorder

# Optional DLC
A3_Data_F_Jets
```

A base-game or DLC addon must be listed once, whatever the number of PBOs
that require it.

Add `--mission PATH` to include the `addons[]` list of a mission PBO. The
`mission.sqm` entry must be stored, not compressed. A compressed or
missing entry is an input error that names the reason.

The command prints the count of provided classes, requirements and
unaccounted entries. It prints one line for each unaccounted entry, with
the requiring PBO and the addon class. `--suggest` prints the external
list format on standard output and writes no file.

The check is advisory. A run with an unaccounted entry exits 0, so a
warning does not stop a build. `--strict` exits 1 when any entry is
unaccounted. A bad input, such as a missing build directory or a
compressed mission, exits 2.

The command has four outcomes:

- All entries are accounted for. The command exits 0.
- An unaccounted entry without `--strict`. The command exits 0 and prints
  the entry.
- An unaccounted entry with `--strict`. The command exits 1.
- A bad input. The command exits 2 and names the path or the reason.

## Update checking

Every command checks for a newer release and prints a notice when one
exists. The result is cached in the user cache directory, as
`uksfta/last-update-check`. On Linux this is `~/.cache/uksfta/`, and on
Windows it is `%LOCALAPPDATA%\uksfta\`. A machine with no cache directory
uses the system temp directory. The command writes nothing to the
repository.

A successful check stays fresh for 24 hours. A failed check stays fresh
for 1 hour, so an offline machine retries once an hour and then continues
at once. The check records no diagnostic when it fails. Set
`UKSFTA_NO_UPDATE_CHECK` to any value to disable the automatic check.
`uksfta version` always checks, even with that variable set, and prints
the install one-liner for your platform.

## Platforms

Steam library discovery is dynamic — the tool reads what Steam records,
it does not guess paths:

- **Windows**: Steam's install path from the registry
  (`HKCU\Software\Valve\Steam`), then `libraryfolders.vdf` for all
  libraries.
- **Linux**: Steam's own `~/.steam/steam` symlink, then
  `libraryfolders.vdf`.
- **WSL**: the Windows Steam install via the registry (WSL interop),
  mapped to its `/mnt/<drive>` mount.

All library folders come from `libraryfolders.vdf`, so extra libraries
(on any drive or mount) are found automatically.

## Installation

### Windows (recommended)

Run this in PowerShell:

```powershell
irm https://github.com/UKSFTA/UKSFTA-Tools/releases/latest/download/install.ps1 | iex
```

This downloads `uksfta.exe`, verifies its SHA256 checksum against the
release's `SHA256SUMS`, installs it under `%LOCALAPPDATA%\Programs\uksfta`,
and adds it to your user PATH. Open a new terminal and run `uksfta --help`
to verify.

### Linux / macOS

Run this in a terminal:

```sh
curl -fsSL https://github.com/UKSFTA/UKSFTA-Tools/releases/latest/download/install.sh | sh
```

This downloads the matching binary, verifies its SHA256 checksum against
the release's `SHA256SUMS`, and installs it to `~/.local/bin` (or
`/usr/local/bin` for a root install on macOS). The installer selects the
asset for Linux x86_64, Linux arm64 or macOS arm64. Open a new terminal and
run `uksfta --help` to verify.

### Manual download

Download the binary for your platform from the [Releases
page](https://github.com/UKSFTA/UKSFTA-Tools/releases) and put it on your
`PATH`:

| Platform | Asset |
| --- | --- |
| Linux x86_64 | `uksfta` |
| Linux arm64 | `uksfta-linux-arm64` |
| macOS arm64 | `uksfta-macos-arm64` |
| Windows x86_64 | `uksfta.exe` |

```bash
# Linux and macOS: rename the asset to uksfta when it has a suffix
chmod +x uksfta-linux-arm64
sudo mv uksfta-linux-arm64 /usr/local/bin/uksfta

# Windows: put uksfta.exe on PATH
```

Each release also includes a `SHA256SUMS` file so you can verify the
binary you downloaded.

Or build from source: `cargo build --release` (Linux, macOS) /
`cargo build --release --target x86_64-pc-windows-msvc` (Windows, matches
the published release binary).
